# K-file / B-file 確定仕様（実ファイル検証済み）

docs/file_format_research.md は有志情報からの二次情報（オフセットに食い違いあり）。
本ドキュメントは実際にダウンロードしたサンプルファイル（2025-01-15, 03-15, 05-15,
07-15, 09-15, 11-15 / 2026-01-15, 03-15, 05-28(SGオールスター), 10-01〜10-03）を
`scripts/derive_offsets.py` で検証し、`src/parse_kfile.py` / `src/parse_bfile.py`
で実際にパースして確認した内容。1872レース/11232出走/3816番組表行が整合（着順数など
矛盾なし）。

## ダウンロードURL

- 競走成績: `https://www1.mbrace.or.jp/od2/K/{YYYYMM}/k{YYMMDD}.lzh`
- 番組表: `https://www1.mbrace.or.jp/od2/B/{YYYYMM}/b{YYMMDD}.lzh`
- 圧縮形式: LZH。Pythonの `lhafile` パッケージで解凍可能（7-Zip等の外部ツール・管理者
  権限は不要）。1ファイルに全24場ぶんの日次データが入っている。
- 文字コード: CP932 (Shift-JIS)。改行は CRLF。

## ファイル構造（共通）

```
STARTK                        (K-fileは STARTK, B-fileは STARTB)
{venue2桁}KBGN
  ...その場のブロック...
{venue2桁}KEND
{次のvenue}KBGN
  ...
```
venueコードは標準の24場コード（01=桐生 … 24=大村）。開催のない場はブロックごと存在しない。

各venueブロック内は「場ヘッダ → 全レース払戻金サマリ表 → レース1詳細 → レース2詳細…」。
レース詳細 = レースヘッダ行 → 列見出し2行 → 区切り線 → 6艇ぶんの結果/エントリ行 →
(K-fileのみ)払戻金詳細。

## K-file 艇別結果行 — 確定オフセット（0-based, 文字インデックス）

実ファイルで `  01  6 3509 池　　　　千　夏 36   53  6.86   5    0.23     1.51.8` の
ような行。**先頭部分（着順〜選手名）は完全な固定長**。後半（モーター〜レースタイム）は
行によって空白幅が変わる／例外時はプレースホルダに置き換わるため、固定長スライスでは
なくトークン抽出で読む（`src/parse_kfile.py` の `_parse_rest_tokens` 参照）。

| フィールド | 位置 | 幅 | 備考 |
|---|---|---|---|
| (先頭空白) | [0:2) | 2 | 常に空白 |
| 着順 | [2:4) | 2 | "01"〜"06"、または例外コード（下記） |
| (空白) | [4:6) | 2 | |
| 艇番(枠番) | [6:7) | 1 | 1〜6 |
| (空白) | [7:8) | 1 | |
| 登録番号 | [8:12) | 4 | |
| (空白) | [12:13) | 1 | |
| 選手名 | [13:21) | 8 | 文字間に全角スペースが入る（例: `川　島　　拓　郎`）。
  `strip`/`split` 厳禁、固定長スライス後に全角スペース除去で名前を復元する |
| モーター番号 | 可変 | 2桁 | トークン抽出 |
| ボート番号 | 可変 | 2桁(右詰め想定) | トークン抽出 |
| 展示タイム | 可変 | 例: `6.86` | 欠場時は `K .` に置き換わる |
| 進入コース | 可変 | 1桁 | 欠場時は `K .` に置き換わる |
| ST(スタートタイミング) | 可変 | 例: `0.23` | フライング時は `F0.02` のように `F`接頭辞＋タイム |
| レースタイム | 可変 | `M.SS.T`形式 例:`1.51.8` | **5・6着は記録されないことが多い**（下記参照）。
  未記録時は `.  .` |

レースヘッダ行例: `   1R       一般　　　　                 H1800m  晴　  風  北　　 3m  波　  2cm`
→ レース番号／レース種別文字列（一般・予選・準優勝戦・優勝戦等。**グレード文字列は
一切含まれない**）／距離／天候／風向／風速(m)／波高(cm)。天候・風向は漢字そのまま、
数値ではない。波高の単位は **cm**（二次情報には「m」説もあったが実データでcm確認）。

### 着順の例外コード（実データで確認できたもの）

| コード | 意味 | 実データでの付随挙動 |
|---|---|---|
| `01`〜`06` | 正常着順 | |
| `F` | フライング | STフィールドが `F0.02` のように`F`+タイムになる。展示・進入・着順は通常通り記録 |
| `K0` | 欠場（選手責任外） | 展示タイム・進入コースが `K .` に置き換わり欠落する |
| `K1` | 欠場（選手責任） | 同上（サンプルでは3件出現） |
| `S0` | 失格（選手責任外） | 展示・進入・STは通常通り記録。レースタイムのみ記録なし |
| `S1` | 失格（選手責任） | 同上 |
| `S2` | 妨害失格 | 同上 |
| `00` | レース不成立 | 他艇の大量フライング等でレース自体が無効になった際、フライング
  しなかった艇に付く。直後に単独行で「レース不成立」とテキストで明記される |

2年分（730日・111,078レース・666,468出走）全件での出現数: 失格(責任)2,697、フライング
2,524、失格(責任外)2,280、欠場(責任外)965、妨害失格532、欠場(責任)298、出遅れ(責任外)42、
出遅れ(責任)22、レース不成立15。`転`/`沈`/`不`/`落`/`エ`/`失` の単漢字コードは2年分でも
一度も出現しなかった（パーサーには定義済みなので、将来出現しても安全に処理される）。

### レースタイムの記録ルール（新たな発見）

1〜4着は**ほぼ100%**レースタイムが記録される。5着は約24%、6着は約24%のみ記録。
「上位のみ記録」という単純な仮説は誤りで、5-6着でもレースタイムが記録される場合と
されない場合が混在する（原因未特定。実運用上は「無ければNULL」として扱えば問題ない）。

## グレード（SG/G1/G2/G3/一般等）の判定方法 — 確定方針

K-file/B-fileにはグレードを示すフィールドが存在しない（レースヘッダの文字列は
「予選/一般/準優勝戦/優勝戦」などの**レース種別**であり、開催自体のグレードではない）。

公式サイトの月間スケジュールページ
(`https://www.boatrace.jp/owpc/pc/race/monthlyschedule?year=YYYY&month=M`) を
確認したところ、各開催セルに `class="is-gradeColorSG"` のようなCSSクラスが付与されて
おり、リンクに `jcd={venue_code}&hd={YYYYMMDD}` が含まれる。これを24場×24ヶ月分
スクレイピングして `(date, venue_code, event_title) -> grade` のマスタテーブルを
作るのが確実な方法。グレード種別は `is-gradeColorSG` / `...G1` / `...G2` / `...G3` /
一般(クラス無し扱いの可能性、要確認) などで判別できる。フェーズ2で実装する。

## フェーズ4: Parquet書き出しと日次更新の結果
